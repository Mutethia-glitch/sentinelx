# Rules for Any AI Working on SentinelX

1. Read the root README first.
2. Read `docs/IMPLEMENTATION_ORDER.md`.
3. Read the specific task before changing code.
4. Read preceding tasks when dependencies matter.
5. Treat each task as a contract.
6. Do not invent product requirements.
7. Do not redesign the architecture without an approved reason.
8. Do not introduce Supabase.
9. Do not expand SentinelX into an offensive-security tool.
10. Do not replace deterministic detection with ML.
11. Do not implement future tasks early.
12. Preserve existing functionality.
13. Test changes.
14. Never commit secrets.
15. Update documentation when behavior changes.
16. Report assumptions instead of silently inventing requirements.
17. At task completion, state what changed, what was tested, and what remains.
